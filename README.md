# 김치로 온라인 버전

GitHub에 소스를 보관하고 Vercel에 배포하며 Supabase에 가게와 제보를 저장합니다. 기존 로컬 버전은 별도 폴더에 남아 있습니다.

## 연결 준비

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다.
2. Authentication에서 운영자 사용자를 생성합니다. 사용자 가입은 비활성화하고, 생성된 사용자 UUID를 확인해 SQL Editor에서 다음을 실행합니다. UUID는 실제 값으로 바꾸세요.

   `insert into public.app_admins (user_id) values ('운영자-UUID');`

3. GitHub에 이 폴더를 저장소로 올리고 Vercel에서 가져옵니다. Vercel 환경 변수로 Supabase 프로젝트 URL을 `SUPABASE_URL`에, **publishable key 또는 legacy anon key**를 `SUPABASE_PUBLISHABLE_KEY`에 넣습니다. 이 값들은 브라우저에 공개되는 값입니다. service_role key나 secret key는 절대 넣지 마세요.
4. Vercel에서 빌드하고 배포합니다. 환경 변수를 변경했다면 다시 배포해야 합니다.

사이트의 `/#admin` 주소를 열어 해당 운영자 계정으로 로그인하면 가게 등록 및 제보 검토를 할 수 있습니다. 주소 자체는 비밀이나 인증 수단이 아니며, 실제 접근 권한은 Supabase 로그인과 운영자 권한으로 제한됩니다. 가게 원산지는 공공데이터에서 확인할 수 없으므로 근거와 확인일을 직접 확인해야 합니다.

- 김치 월드컵의 우승 결과와 인기 순위를 사용하려면 `supabase/worldcup-migration.sql`을 실행하세요. 순위는 사람 수가 아닌 완료된 게임의 우승 횟수입니다.

- 김치요리 월드컵의 우승 순위를 사용하려면 `supabase/kimchi-dish-worldcup-migration.sql`도 실행하세요. 김치 종류 월드컵과 별도로 집계됩니다.

- 리뷰 사진을 사용하려면 `supabase/review-photo-migration.sql`을 실행하세요. 사진은 브라우저에서 JPEG로 줄여 리뷰 데이터에 저장하고 공개하며, 가게 상세에는 최근 리뷰 사진을 대표로 표시합니다. 사진은 각 리뷰에 최대 100,000자(인코딩 포함)로 제한되며 데이터베이스 용량과 전송량을 사용합니다.

## 운영 주의

- 사이트 의견 기능을 사용하려면 `supabase/feedback-migration.sql`을 실행하세요. 사용자는 익명으로 의견을 보내고, 운영자 메뉴의 사이트 의견 탭에서 검토할 수 있습니다. 의견은 공개되지 않으며 개인정보를 입력하지 않도록 안내합니다.

- 기존 Supabase 프로젝트에 리뷰 기능을 추가하려면 배포 전에 SQL Editor에서 `supabase/reviews-migration.sql`을 실행하세요. 새 프로젝트는 `supabase/schema.sql` 실행 후 같은 파일을 실행합니다. 리뷰는 별명·별점·내용이 공개되며 운영자는 가게 상세에서 삭제할 수 있습니다.
- 첫 방문 시 브라우저가 위치 권한을 요청합니다. 허용하면 현재 위치로 지도를 이동하고, 거부하거나 위치를 찾지 못하면 서울을 표시합니다. 위치는 서버에 저장하지 않습니다.
- 제보 검토에서 전체 선택과 선택 해제, 선택 삭제, 선택 제보 순차 검토를 지원합니다. 제보를 하나씩 확인하고 등록해야 하며, 위치 좌표가 없으면 지도 마커가 표시되지 않습니다.
- 공개 제보는 누구나 등록할 수 있고 현재 별도의 자동 스팸 방지나 사용량 제한은 없습니다. 실제 공개 전 접근량 제한이나 CAPTCHA 등을 추가하고 사용량을 모니터링하세요.

## 초간단 사진 제보 (v2)

- 장소검색 API가 연결되어 있지 않아 식당 이름 + 동네 + 원산지 표시판 사진 세 입력을 사용합니다. 주소 찾기는 관리자 화면에 유지합니다.
- `supabase/migrations/20261102044439_simple_photo_reports.sql`을 먼저 적용한 뒤 웹을 배포합니다. 기존 제보도 계속 접수·검토할 수 있습니다. 새 프로젝트는 schema.sql 이후 이 파일을 적용합니다.
- 사진은 JPEG/PNG/WEBP 최대 15MB, 6천만 화소 이하를 받아 최대 긴 변 2000px JPEG로 다시 인코딩합니다. 최대 1,400,000자이며 원본 파일명·EXIF/GPS를 보내지 않습니다. 작은 글자가 읽히는지 미리보기를 확인해야 합니다. HEIC는 JPG로 변환해야 합니다.
- 사진은 reports.data에만 저장되며 기존 RLS로 운영자만 조회할 수 있습니다. 공개 stores로 복사되지 않습니다. 관리자 검토 화면에서 사진을 보고 실제 확인일·원산지 근거·상세주소를 입력해야 등록할 수 있습니다. 제보 시각은 DB created_at에도 자동 기록됩니다.
- 제출 실패 시 입력과 사진을 유지합니다. 완료 시 검수 대기 안내를 표시합니다. 기존 공개 가게 정보는 변경하지 않습니다.
- 검증: 390×844 모바일 브라우저에서 사진 필수·잘못된 형식·압축·미리보기·실패 후 재시도·완료·재열기 초기화·기존 및 신규 관리자 검토를 확인했습니다. 실제 휴대폰 카메라와 iOS 사진 선택은 기기에서 추가 확인이 필요합니다.
- 데이터베이스 접근 권한은 SQL의 RLS 정책으로 제한됩니다. 운영자 UUID를 추가하기 전까지는 아무도 관리할 수 없습니다.
- Supabase 사용자 가입을 끄고 강력한 암호를 사용하세요. DB 공급자의 백업 정책과 요금제 및 사용량을 확인하고 주기적으로 가게 데이터 백업을 내려받으세요.
- 주소 검색은 외부 Nominatim 서비스에 입력한 가게 주소를 전송합니다. 지도 타일은 OpenStreetMap을 사용합니다.
- 기존 로컬 버전에 등록한 자료는 별도입니다. 운영자 메뉴에서 백업을 보관한 뒤 온라인 버전에 다시 등록하세요.
